Unapplied redaction marks made in other programs now open as Inkbar marks. You can select, move, delete and apply them like your own. This release also brings a large set of new reading and drawing features to `@inkbar/engine`.

### New

- Redaction marks from other programs open as editable marks. Apply removes the content under them, and the confirmation counts them. A mark keeps its area, fill colour and overlay text. It stays locked in an encrypted file, or when another program's annotation replies to it.
- `@inkbar/engine` can draw text in fonts a file does not embed. Pass `fallbackFonts` to `createEngine`, using `fontUrls(base)` from the new `@inkbar/fonts` package. The engine fetches only the Japanese, Chinese, Korean or default fonts a page needs. A render lists any it could not get in `missingFonts`.
- `renderPage` takes `region`, `size`, `rotation` and `hide`. Use them to draw part of a page, at an exact pixel size, turned, or without chosen annotations. It also takes a `signal` that stops a render already under way. It now draws form widgets too.
- `pageInfo` reports a page's `userUnit`.
- New engine reads:
  - `pageText` for characters with their boxes and fonts.
  - `pageLinks`, `outline` and `namedDestination` for links and navigation.
  - `documentFacts`, `pageAnnotations`, `formFields`, `scripts` and `structureOrder` for a file's details, annotations, form, scripts and annotation order.
- `renderAnnotations` in `@inkbar/engine` draws chosen annotations on their own, each in a named appearance state.

### Improved

- Screen readers now announce each radio button by its own option, such as "Adult, Membership", not just its place in the group. This comes with new translations in English, French and German.
- Search and highlights on vertical text now cover the right part of the column. A column split across two fonts now reads as one phrase.
- If reading a document's outline fails, the next request tries again instead of keeping the failure.
- The engine rejects bad render options with `invalid-argument`. Calls made after `destroy()` reject the same way.

### Fixed

- In forms with a calculation order, fields listed after a parent field with no widget of its own are now calculated. Before, they were skipped and a script error was reported.
- Destroying a document while text was loading no longer logs a console warning. `doc.text()` and searches still running at that moment now reject with `DocumentDestroyed` instead of never settling.
- The engine now draws content that uses Screen or SoftLight blending directly on the page. It also no longer leaves a pale fringe on text edges under a highlight.
- Corners of redaction marks stored in other orders no longer draw as a bow-tie.
