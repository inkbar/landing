Search

Inkbar searches the page text. Your users get a find bar that floats over the pages, and your code gets doc.search, which returns each match with its place on the page. The bar runs on doc.search too, so the bar and your code find the same matches for the same query.

The find bar

Section titled “The find bar”

InkSearchButton opens the bar, and InkFindBar is the bar itself. Put the button in a toolbar. Put the bar anywhere inside InkRoot: it moves itself into the viewport, and the theme floats it over the top-right of the pages. It stays hidden until it opens.

  • Vue
  • React
  • Svelte
  • Plain DOM

In plain DOM the bar does not move itself. Append it to [data-ink-viewport-root] so the theme can float it.

The bar has a field, the match count, previous and next buttons, a match-case toggle and a close button. As the user types, Inkbar starts searching from the current page, highlights every match and scrolls to the first one it finds.

  • Enter steps to the next match and Shift+Enter to the previous. Both wrap around at the ends of the document.
  • Escape or the close button hides the bar, clears the highlights and sends focus back to where it was before the bar opened.
  • Ctrl+F (Cmd+F on a Mac) opens the bar, but only while focus is inside the viewer and a bar is mounted. Text selected on the page, up to 200 characters, becomes the query. Anywhere else on your page, the browser’s own find keeps the key.
  • The count reads “3 of 17”, with a trailing “…” while pages remain to scan, or “No results”. A live region tells screen reader users the match number and page as they step.
  • Pressing the search button while the bar is open moves focus back to the field.

The bar has no whole-word or regular expression toggles. doc.search takes both, below.

InkSearchButton takes asChild (as-child in Vue, the child snippet in Svelte), like the other toolbar controls. In React and Svelte, the bar handles Escape and stops it, so an onKeyDown (onkeydown in Svelte) you pass to InkFindBar never sees that key.

Your own control

Section titled “Your own control”

useSearch() returns the state behind the find bar and the actions that change it. In plain DOM the same object is viewer.search, and plugins get it as ctx.search.

State What it holds
open Whether the search is open
query The query
matchCase Whether case must match
hits The matches found so far, as search hits, in order
current The index of the current hit in hits, or -1 when there is none
scanning Whether pages remain to scan
Action What it does
open(query?) Opens the search, with a new query if you pass one
setQuery(query) Sets the query and searches again
setMatchCase(on) Turns match case on or off and searches again
next() Moves to the next hit and scrolls to it
previous() Moves to the previous hit and scrolls to it
close() Closes the search and clears the hits. It keeps the query and toggle

open() searches and draws the highlights even with no find bar on the page, so you can build your own. In Vue state is a ref, in React a plain value, and in Svelte a getter, so read it through the returned object. In plain DOM viewer.search.state is a readable. Before InkRoot mounts, and during server rendering, the state reads closed and the actions do nothing.

Searching from code

Section titled “Searching from code”

doc.search(query, options) finds a string or a regular expression in the open document. Iterate the result with for await to get hits as Inkbar scans each page, or call all() to wait for the whole list:

A string matches the text as a reader sees it. It ignores case, accents, ligatures and curly quotes, and it finds words split across a line break or a hyphen at the end of a line. A regular expression runs on that same text.

Option What it does
matchCase Case must match. Default false. A regular expression ignores it and follows its own i flag
wholeWord A hit must not have a letter, digit or underscore on either side. Default false
pages The page indices to search, from 0, in the order you give. Default: every page, first to last
signal An AbortSignal. Aborting it stops the scan, which then throws the signal’s reason

The scan yields to the browser between pages, so a long document keeps the page responsive. To stop a search the user no longer wants, abort it:

Closing the document stops a running scan too, with an AbortError. Plugin commands receive a signal that aborts when the document closes, so pass it straight through.

Search hits

Section titled “Search hits”
Field What it holds
page The page index, from 0
start, end Offsets into doc.pageText(page)
text The page text the hit covers
quads One quad for each run of text the hit touches, in PDF user space
rect The box around quads
exact Whether every quad follows the page’s own glyph positions
before, after Up to 40 characters of page text on each side, with whitespace collapsed

Each quad follows where the page draws each glyph, and spans the font’s full height, so it covers ascenders and descenders. You can pass quads straight to a text markup annotation, such as a highlight or a redaction mark.

exact is false when Inkbar could not match some of the text to the page’s glyphs. Right-to-left and vertical text cause this, as do some unusual files. Inkbar then cuts that quad at estimated widths, which can fall short of the glyphs. Pad those quads before you use them to cover text, as you would for a redaction.

page and start together identify a hit. The same query on the same document gives the same pair, so use them as a key, for example as a record id.

In a plugin

Section titled “In a plugin”

Inkbar has no “redact all” or “highlight all” button. Actions on every match belong in a plugin. This one adds a command that finds National Insurance numbers, keeps each as a record, and draws a mark over it:

The (page, start) key makes addMissing skip a number the plugin already holds, so running the command twice adds nothing new. Place the command with <InkCommand id="ni-numbers.find" />. To turn a record into a redaction mark the user can undo, link the records to redact annotations with found.annotates, as Writing a plugin shows.

The plugin that setup receives also carries the viewer’s search as plugin.search, the same object as useSearch(), for a plugin that opens the find bar or reads its hits.

Theming

Section titled “Theming”

@inkbar/theme colours the matches with two tokens:

Variable Used for
--ink-search-hit Every match
--ink-search-current The current one

The theme declares them on [data-ink-root], so set yours there:

The theme draws the matches in a layer that multiplies with the page, so the text stays dark on top of the colour and the matches sit under the annotations. Pages stay white in dark mode, so one pair of colours serves both themes.
